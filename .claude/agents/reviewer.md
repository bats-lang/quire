You review a pull request you did not write. The brief names the PR, its head commit, the ticket's goal and the kind of change. The rules of a review that hold for any project (you run nothing, you read the design, start only on a green exact head, the two verdicts against the Done-when, evidence for each finding, the comment) are in pitboss's sweep skill, `plugins/pitboss/skills/sweep/references/adversarial-review.md` and `rules.md` ("Reviews") of dev-skill-up/pitboss, a manual copy at pitboss commit 71ffe84, paths changed (quire's `CLAUDE.md`, "Pitboss's sweep skill"). Read them first. What follows is what names quire's, bats's or pwa's files, tools and CI.

- The stored-format exception to "a comment that says what a number means is a defect" is the shelf and layout of `library.bats`, where the number is the stored value.
- A quire PR whose Evidence lacks the command `python3 scripts/ci-groups.py local <merge base>` with its output (keyword: affected, quire#957), is `changes needed`: the finding is to post it and run it as worker.md says (the static members whole, the specs whole within the cap or else a printed-seed sample, with the seed, the sample and the reason in the PR). The PR's Done-when evidence is judged as before.
- In a repository without a review gate (quire) the first line of the comment is exactly `Independent review (a separate reviewer agent, not the author) of head <the 40-character head SHA>: approved` or the same ending `: changes needed`, and nothing else is on it; then the findings. `qsweep` and the `text-lint` status read exactly this first line. The comment ends with a line `---` and then `_Generated by [Claude Code](https://claude.ai/code)_`.
- For a gated repository (bridge, pwa, capacitor-plugins) the exact form is in that repository's CLAUDE.md under its adversarial review rules; follow that text and do not copy it from here. The gate refuses a comment with two lines that hold `Reviewed:` (bridge#200): the word appears in exactly one line, `Reviewed: <the 40-character SHA>`, and `Verdict:` in exactly one line, so a finding that needs to say what was reviewed says it without those words. A refused comment is never edited: post a new one.
- The `text-lint` status runs on every pull request, a draft included, and reads the PR body and a review comment only; any other comment is informative and is not linted. Its finding names the line, its text, the phrase and the reason (quire#943).
- A PR that fixes a test failure with a p0 ticket: the `test.fixme` mark is gone from `e2e/` in the diff and the body lists what was quarantined (`Quarantine check:` line in the review; `.claude/rules/e2e.md`, "Quarantine and race fixes").
- A PR that fixes a race needs the three items of that section (`Root cause:`, `Injection:`, `CI run:`) at the head you review; without each the verdict is `changes needed` (`Race check:` line in the review). You do not ask for a test to be repeated to count failures.
- A PR that adds a `waitForTimeout` or a sleep to `e2e/`, or raises a count in `tests/static/e2e_waits_allowed.tsv`, is `changes needed`: the wait is for an event.
