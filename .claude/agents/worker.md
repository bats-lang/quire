## Design

- Data read into one value (a string, a buffer, an array) has a size that value can hold; say the bound or stream it. The one exception is a stored format (the shelf and layout of `library.bats`, where the number is the stored value).

## Where you work, and how long a run is

- The check command is the one in `.claude/rules/ci.md`, "Checking locally before a push": `BATS_SLOTS=1` through the env file, no `timeout` wrapper. The first build of a new checkout is cold (10 to 15 minutes); a command that can run past the Bash tool's cap of 600000 ms runs with `run_in_background` and its log is read until it ends, inside your turn; nothing else is left running when you finish. Do not start two heavy runs at once on this 4-core machine.
- **Affected (quire#957, keyword: affected).** Before every push, run `python3 scripts/ci-groups.py local $(git merge-base origin/main HEAD) --run <repository>` for your diff (quire). It lists the whole selected population on standard output (`check`, `checkers`, every fixture that reads a changed file, every e2e spec the rule selects), which is CI's affected rule at the granularity of a fixture, not a list you build with `grep`. The static members it selects run whole. The specs run whole when they fit the 10 minutes (`--specs N`, default 12); otherwise a seeded sample of the selected specs runs and the command prints the seed, and CI runs the rest. This is the one relation between the list and your 10-minute cap: the cap bounds the specs, never the fixtures. The seeded sample (`--sample N --seed S`) is added to the list, never put in its place. The PR's Evidence has the command and its output, the seed, the sample and why it suffices.
- A local e2e run needs tracefs, and a restarted container may have none (quire#958): when the preflight says `no tracefs instances directory`, run once `grep -q tracefs /proc/mounts || mount -t tracefs nodev /sys/kernel/tracing` (the allowed command; `.claude/rules/ci.md`, quire#765) and run the spec again. Run no other `mount`.
- Regenerating `bootstrap/c` is local, takes as long as it takes, and is done last, after the sources are fixed, built with the existing bats compiler and checked to do what is needed.
- Reject expects are written with `bats fixtures --bless` (bats#522) after the last edit of a module, never by hand and never by repeated population runs. Until bats#522 merges, write each from the observed error of one run of that snippet.

## Pushing and the PR body

- Push with `qsweep push <git push arguments>`: it prints `qsweep pressure` and runs `git push` only when it says `runner pressure: none` (exit 0). If `qsweep pressure` exits non-zero, hand back at once, naming where you stopped and the SHA of what is unpushed; never loop, retry or sleep for the pressure to clear (owner, 2026-10-25T17:58:35Z, transcript line 95384, on a loop of `qsweep pressure` and `sleep 60`: "Runner pressure should cause hand back, not whatever this is"). A pressure hold never empties an agent row: the orchestrator pushes your commit when the hold ends and starts the next item.
- The PR body's first line is `Fixes #N`, it has a line `Head: <the 40-character SHA>` that is the head, an `Evidence` section, and it ends with the line `🤖 Generated with [Claude Code](https://claude.ai/code)`; the session's GitHub proxy replaces that line with the footer `_Generated by [Claude Code](https://claude.ai/code)_` when the body is written through `gh api`, and the lint accepts either. `python3 tests/static/guidelines.py --pr-body <file> --head <sha>` checks the form, and `.github/workflows/text-lint.yml` runs it on every push and edit. After every push, edit the body for the new head.
