Read them first. What follows is what names quire's, bats's or pwa's files, tools and CI.

## Design

- Data read into one value (a string, a buffer, an array) has a size that value can hold; say the bound or stream it. The one exception is a stored format (the shelf and layout of `library.bats`, where the number is the stored value).

## Tests

- A test failure that gets a p0 ticket is quarantined in the commit that files it: `test.fixme('#N ...')` on every project (`.claude/rules/e2e.md`, "Quarantine and race fixes"). The fix removes the mark, and the PR body lists it in a line `Quarantine: ...`.
- A fix for a race (a failure that depends on the runner's speed, a fixed wait or an order of events) merges only when its PR body has a line `Race: ...` and the three items of that section, each a line of its own: `Root cause: ...`, `Injection: ...` (the raw output is in Evidence) and `CI run: <URL>`. No test is repeated to count failures. No new `waitForTimeout` or sleep in `e2e/`: wait for an event.

## Where you work, and how long a run is

- **Short jobs run locally, CI runs the rest** (the owner's words, as quoted in quire#911, filed 2026-10-26T17:49:33Z: "I said "no long jobs", not "try to find clever ways to run them". Short jobs locally, CI for the rest"): a check that takes more than a few minutes locally is left to CI, not run here (foreground or background, whole or split); you commit, push when the push rule below allows, and CI is the evidence, named in the PR body as CI's; nothing is left running at hand-back. What runs locally is incremental, in that checkout, and finishes in a few minutes: a named fixture or one shard of a population (fixtures, specs, tests); the rest of the population is CI's, and the PR body says so. No two heavy runs at once on this 4-core machine.
- The check command is the one in `.claude/rules/ci.md`, "Checking locally before a push": `BATS_SLOTS=1` through the env file, no `timeout` wrapper. The first build of a new checkout is cold and takes longer than a few minutes, so it is left to CI: the next ticket is a new branch in a warm checkout, and a push from a cold one is checked by CI.
- In quire, a worktree you make with `git worktree add` has the pre-push checks installed: the sweep (`qsweep`) sets `core.hooksPath .githooks` in the repository's own config, which every worktree inherits (`.claude/rules/ci.md`, "The pre-push hook"; the sweep prints `HOOKS-NOT-INSTALLED` for a checkout whose effective value differs, and a `--no-verify` is never used). Push with `qsweep push`, which reads `~/quire.env` for the hook's variables; write `bats.pin` once beside each compiler you have (`.claude/rules/ci.md`).
- **Affected (quire#957 and #1006, keyword: affected).** Before every push, run `python3 scripts/ci-groups.py local $(git merge-base origin/main HEAD) --run <repository>` for your diff (quire). It lists the whole selected population on standard output (`check`, `checkers`, the fixtures `bats fixtures tests/static --list-affected` lists for the paths of your diff, every e2e spec the rule selects), which is CI's affected rule with bats's own fixture selection, not a list you build with `grep`. It needs the package repository (`--run <repository>` or `BATS_REPOSITORY`) and `QUIRE_STATIC_WORK` set in the env file, so that bats's memo is kept; without a memo bats lists every fixture, and a bats that fails fails the command. You run from the list only what finishes in a few minutes (the rule above): `check`, `checkers` and a named fixture or spec; the rest of the list is CI's, and CI's run is the evidence for it. The PR's Evidence has the command and its output.
- A local e2e run needs tracefs, and a restarted container may have none (quire#958): when the preflight says `no tracefs instances directory`, run once `grep -q tracefs /proc/mounts || mount -t tracefs nodev /sys/kernel/tracing` (the allowed command; `.claude/rules/ci.md`, quire#765) and run the spec again. Run no other `mount`.
- Reject expects are written with `bats fixtures --bless` (bats#522) after the last edit of a module, never by hand and never by repeated population runs. Until bats#522 merges, write each from the observed error of one run of that snippet.

## Pushing and the PR body

- Push with `qsweep push <git push arguments>`: it prints `qsweep pressure` and runs `git push` only when it says `runner pressure: none` (exit 0). If `qsweep pressure` exits non-zero, hand back at once, naming where you stopped and the SHA of what is unpushed; never loop, retry or sleep for the pressure to clear (owner, 2026-10-25T17:58:35Z, transcript line 95384, on a loop of `qsweep pressure` and `sleep 60`: "Runner pressure should cause hand back, not whatever this is"). A pressure hold never empties an agent row: the orchestrator pushes your commit when the hold ends and starts the next item.
- The PR body's first line is `Fixes #N`, it has a line `Head: <the 40-character SHA>` that is the head, an `Evidence` section, and it ends with the line `🤖 Generated with [Claude Code](https://claude.ai/code)`; the session's GitHub proxy replaces that line with the footer `_Generated by [Claude Code](https://claude.ai/code)_` when the body is written through `gh api`, and the lint accepts either. `python3 tests/static/guidelines.py --pr-body <file> --head <sha>` checks the form, and `.github/workflows/text-lint.yml` (the shared lint of repository-prototype, called by commit) runs the form of the body on every push and edit. After every push, edit the body for the new head.
