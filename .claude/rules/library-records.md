# The library as records, reading progress and replacing a file

## The library is stored as records (#354)

Each book is a record, `library/book/<14 hex digits>` (its id as two 28-bit halves,
7 digits each), and the collections another, `library/index`. They are read together
by their prefix (`libstore_read`, bridge's `idb_get_prefix`) and saved one at a time,
so a change to one book writes one book's bytes and a record damaged in one place
costs that record's damaged part and nothing else.

**The format** is `QREC`, a kind (book, index), the version of the format that wrote
it (1) and the least version that can read it (1, the reader's `READER`), then chunks
as PNG has them: a u32le length under 2 to the 20, a 4-byte tag, the data and a CRC-32
(IEEE, 0xEDB88320) as its low 16 bits and then its high 16 bits, little endian, over
the tag and the data; the last chunk is `IEND`. A record is a set of groups, one chunk
each, written in ascending tag order (a book's: `AUTH BOOK COLL ELSE FNSH ORDR PLCE
SERI SHLF SIZE TIME TITL`, the index's `LEGA NAMS`) and read by tag, in any order.

* A chunk of a tag this version does not know is kept as it is, at the end, when its
  first letter is lower case (ancillary, as in PNG), so a newer Quire's addition
  survives this one's save; a capital one (critical), or a least version over
  `READER`, makes the record `Newer`; a first four bytes that are not `QREC` make it
  `NotQuire`. A decode is one of five outcomes (`recres`: `rr_ok`, `rr_loss`,
  `rr_notquire`, `rr_newer`, `rr_damaged`). `rr_damaged` is left for a record with no
  chunk to keep: cut inside its 7-byte header, or of another kind than the reader's.
* **Chunks are looked up by tag, in any order, and a tag twice is a loss that is used**
  (#510). Protobuf, PNG, EBML and CBOR all leave order to the writer. `CANON`
  (`src/schema.bats`) puts the chunks in the order of the groups before they are read:
  for each group `EXT` takes every chunk of its tag out wherever it stands and chooses
  the last whole one (else a damaged one, else none); what is left follows, as chunks a
  newer Quire added. A tag twice is damaged but recoverable: the later whole chunk wins
  (a later one with a bad CRC does not hide an earlier whole one), the earlier ones are
  dropped and their tag is among the `lost` of `rr_loss`, so the book is a `LossyBook`,
  said once, and the next save writes one chunk of each tag and keeps the old bytes
  under `library/damaged/<id>/<crc>`.
* A chunk this version does not know is kept whole and in order, twice if it was there
  twice (it is opaque; PNG allows several `tEXt`). One whose tag is a group's is not kept
  (`NOTKNOWN`). What makes the written chunks read back as they were is a proof the
  writer carries: the tags of the groups are all different (`SPECSOK`, generated by
  `scripts/gen-record.py`) and the tag of a kept chunk is none of the groups'
  (`extrasv`), so `senc_canon` shows the chunks written are their own canonical ones
  (`tests/static/reject/codec-group-twice-earlier-wins`, `codec-group-twice-not-said`).

**Recover fanatically** (the owner's rule for #510): if a bug in Quire damages a record
the reader must still read the book. In order: (1) usable with defaults or substitutes
(a lost or absent group, a tag twice, a bad CRC, a lost required group, a cut in the
chunks); (2) said, once, in the notice (#507: Copy details with the record's id and what
was lost); (3) the old bytes kept under `library/damaged/<id>/<crc>` when a save repairs
it; (4) `Unusable` only for what cannot be read as a record at all (`NotQuire`), has no
chunk and no header to read, or is a newer Quire's (`Newer`, not damaged). **A bug that
leaves a record unusable is fixed by widening the recovery, not by setting the record
aside.**

* **A group the record needs, lost, is substituted.** The `LOSES(requirement)`
  constructors of `SDEC` cover a group absent, with a bad CRC or fields that do not
  parse, for `req` and `opt` alike (`added` keeps its own: absent is silent). A book
  whose TITL is lost is "Untitled", whose AUTH is lost has no author, whose BOOK is lost
  has ids 0 in the record and the key's in the library (`SUBSTITUTES` in
  `scripts/record_tables.py`, else 0 and empty). **The key wins** (`_read_book`,
  `_keyed_book` in `src/libstore.bats`): a record under `library/book/<id>` is the book
  `<id>` whatever ids it holds, and its save writes the key's ids. Such a save
  (`_repaired`) writes the image whole and keeps the old bytes, in the same transaction.
  `tests/codec` and `e2e/library-records.spec.js` lose each of AUTH, BOOK and TITL.
* **What a record lost and the book's file can say is read again from the file**:
  as a book is reopened from storage (`Reopen` in `_opf_store`, `src/import.bats`)
  `lib_rebuild` (`src/library.bats`) takes from the OPF what a field holds only as a
  placeholder: the title "Untitled", the author "Unknown", a series with no name or
  position, no direction of the text, no file size. A field holding any other value is
  never changed, and what the reader made (place, shelf, collections, finished, minutes,
  order, notes) is never read from a file. Not rebuilt: the cover, the progress weights,
  the accessibility summary. A rebuild that changes something saves at once.
  `e2e/old-library.spec.js`.
* **The version before.** `library/previous/<id>` holds a book's record as it was before
  a save and `library/stamp/<id>` when it was last written (4 bytes, seconds since 2025;
  read once at load, `_stamps`). A save keeps the record it replaces as the previous
  version only when that record was last written 60 seconds ago or more (an unknown stamp
  counts as old) and decodes whole (KOReader's rule, on the age of the file replaced, so
  a bug that damages a record at each save leaves the version from before the first). A
  book whose record is `UnusableDamaged` (cut inside its header, empty, over `RECORD_MAX`,
  or a cut that kept none of AUTH, BOOK and TITL) and that has a previous version is read
  from it (`_recover`, a `LossyBook`). Emptying the Trash deletes the record, its previous
  version and its stamp together. The stamp is a key of its own, not a group (it is
  bookkeeping, not the book's). A lost reader state needs no notice action: a lost group reads as a substitute with the stamp 0, so the next sync's merge takes the store's (or the Auto Backup file's) value (`e2e/sync-lost-groups.spec.js`).
* **A record cut in its framing is a loss and keeps the chunks before the cut** (#614):
  a record that ends before its end chunk, has a length past its end or over the limit,
  has bytes after the end chunk, or whose end chunk holds data is not `rr_damaged`; each
  chunk is framed and CRC-checked by itself, so those read whole before the cut are kept,
  the groups after it are lost with their substitutes, and the record is `rr_loss`.
  * `src/seq.bats`: `seqres` is `sq_ok(chunks)` or `sq_cut(chunks, cause)` carrying the
    chunks read whole before the cut, and the cut is named in the loss by a constructor of its
    own (`lt_cut`); the types forbid a cut that claims an unread chunk
    (`tests/static/reject/codec-cut-*`). A cut does not hide a newer Quire's record
    (`JOIN_newer`).
  * A cut that leaves a required group missing: the key wins; a cut before BOOK has ids 0
    and takes the key's, repaired at the next save; title and author come back from the
    file when reopened. Trailing bytes and an end chunk with data are cuts too (the loss
    notice is more than the facts need; the next save writes the record clean).
  * The collections' record is cut the same way (`IR_loss`, `LossyIndex`); it has no
    previous version, so it is always read as the cut record.
  * A cut that kept none of AUTH, BOOK and TITL reads the version before when there is
    one (`_cut_kept_nothing` on the loss list's tags, an `EmptiedBook`, which `_recover`
    replaces); a cut that kept at least one keeps its own, newer groups. The test is on
    tags, not a proof.
  * Tested: `tests/codec` (a record cut at every length), `e2e/library-records.spec.js`.
* Tests: `tests/codec` (the chunks in the opposite order, a group twice either way),
  `e2e/library-records.spec.js` (every rotation, the reverse and seeded shuffles open as
  the same book and are not written by opening; a group twice; an unknown chunk twice).

**A group added later is not loss when it is absent** (#497). A group has one of three
modes in `scripts/record_tables.py`: `req` (the record needs it), `opt` (every version of
the format has written it: absent is damage, present and damaged is loss) and `added`
(added after records were written: absent is nothing, the record reads whole with the
group's defaults; present and damaged is loss). `prog`, `snum` and `tdir` are `added`,
and every group added from now on is. The format version cannot tell them apart (records
in the wild are all version 1 with any prefix of the groups), so it is the group's own
mode. The decoded record says which groups were absent (`rx_mk(format, least, vals,
extras, absent)`); writing an absent group writes nothing, with the proof that the next
chunk is not the group's (`SENC_absent_*`, `TAGDIFF`). The app only ever writes records
with every group (`record_write` has `ab_nil()`), so the first save of an old record
writes the groups it lacked; opening writes nothing and keeps no copy. A PNG decoder
must not require an ancillary chunk, protobuf reads an absent field as its default, and
SQLite's `ADD COLUMN ... DEFAULT` leaves old rows valid.

**The rule cannot be forgotten, and every table that shipped opens** (#515). A group is
added only as `added` and named in `RELEASES` in `scripts/record_tables.py` with its
commit. `tests/static/groups.py` (in `checkers`) fails a group of the other modes after
the first table, a group not in `RELEASES`, and a change that does not add the library of
the table before it: `e2e/old-library.spec.js` has one library for each table that
shipped (`SHAPES`) and each opens with every book, nothing said, nothing to set aside, no
record changed or copied on open, and a save writes the current groups. The QLB1 to QLB6
formats of the old whole-library record are in `e2e/library-records.spec.js`. On the
android project the app syncs as it opens and its records land when that sync ends, so
`syncEnded` / `reloadSettled` (`e2e/legacy-library.js`) take "sync-state" away before a
reload and wait for the sync's end; a spec changes and snapshots the store only when the
app has stopped writing it.

## The codec is proven

`src/bytes.bats`, `crc.bats`, `chunk.bats`, `seq.bats`, `fields.bats`, `schema.bats`,
`record.bats`; the tables are in `scripts/record_tables.py`, and `bookrec.bats`,
`indexrec.bats`, `bookimage.bats`, `indeximage.bats` are generated from them by
`scripts/gen-record.py` and `scripts/gen-image.py`, so a field is added in one place.
Byte strings are a datasort (`bytes`), `blist(bs, n)` linear lists indexed by them.
Reading is a relation between bytes and its result (`DECODES(sp, kind, bs, res)`), writing
another (`ENCODES(sp, kind, x, bs)`), and the laws are lemmas the compiler checks, so a
codec that is not the inverse of itself does not type-check:

* `encodes_decodes`: what is encoded decodes to what was encoded, exactly (no padding is
  accepted, no kept chunk is lost: `tests/static/reject/codec-drops-unknown-chunk`);
* `decodes_functional`: bytes decode to one result;
* a record read and saved never changes in meaning: `record_write` of the very values a
  read gave is `ENCODES` of the same record, so decode(encode(decode(x))) = decode(x).
  (`decodes_encodes`, the bytes decode to x so encoding x gives the same bytes, is gone:
  out of order bytes are written in ascending order);
* `record_read` is total, `record_write` returns the `ENCODES` proof of the bytes it made;
  the stored CRC is compared with `CRCP`'s before a chunk is `ok`.

**The round trip is proved, from the value to the bytes and back.** A stored book is a
`book_image(x)` indexed by the book `x` it holds (`bookx_mk(...)`): each number an
`int32v(n)`, each string a `bstr(bs)` (a `barr` whose cells are proved to hold the bytes).
`book_record_new` / `book_record_image` / `book_of_image` / `book_image_of` keep it;
`book_roundtrip` (and `index_roundtrip`) proves bytes written from `x` and read back as a
book `y` make `x = y`; `book_image_roundtrip` is the whole as a function
(`tests/static/reject/image-roundtrip-another-book`). Outside the proof is only what is
outside quire: bridge's atoms that write an array to IndexedDB and fill one from it, the
array package's memory primitives, arith's C operators (`and_proved`, `or_proved`,
`xor_g1`) and the prelude's `/`, each tested where it lives. The copy of a library
`Book`'s fields into an image and back (`_image_of_book`, `_book_of_image`) goes through
`book_image_make`, which refuses a number that is not 32 bits. `tests/codec` runs the
whole on bytes and numbers at the edge (damage to every byte, every prefix, fuzz) as a
check of those boundaries, not as the proof.

**The solver is 32-bit under the -int build, and a context can be contradictory without
any large literal** (#594): a constant or coefficient of 2 to the 30 or more in a
hypothesis makes the context contradictory and anything is proved; so do nested divisions
(`h/256 + 256*(l mod 256)`), a product passing 2^32 (`v == 4096*b`) and matched copies of
arith's `ROTR1`. CI uses the infinite-precision GMP build, whose own risk is a proof it
cannot answer in time, not a false one it accepts (bats's setup action's caps end that);
`tests/static/solver/` (standalone fixtures run by `tests/static/solver.py`, the `solver`
member) holds the cases. `tests/static/literals.py` fails the checkers on a literal of 2 to
the 29 or more in `src/` (a run-time value marked `(* wide *)` is exempt). Rules for a
proof's arithmetic:

* **Keep the magnitudes down, and name the digits.** A statement is made of steps that
  divide (or take `mod`) by a constant of at most 16 at a time and numbers built a digit at
  a time (`b + 256 * m`), never a closed form with nested `/` or `mod`, a product of two
  variables, or two equations over the same variables with scales. A proof that only the
  infinite-precision solver can answer in time is split. `tests/static/proofs_audit.py`
  lists the places that may not (report only).
* **A false variant of every lemma is rejected.** `tests/static/mutation_check.py` makes
  them (a numeric index plus one, a guard's `==` shifted by one, a bound tightened by one,
  a byte string consed with a byte, an argument of another sort replaced by a fresh
  variable, each part of a tuple result, `[1 == 2] void` in place of a guard) and the
  compiler must reject each (`--root DIR --run WORK file.bats` for another package,
  `--ats-home DIR`, `--inplace` for a recursive `#pub` lemma). An accepted mutant is a
  vacuous proof (or a mutation that is true: `tests/static/mutation_known.txt`) and is filed
  as its own p1 issue with the minimal case. A lemma no operator reaches (a `FALSEP`,
  `EQFD` result) gets its false variant as a fixture in `tests/static/solver/reject/`. The
  checker is tested by `tests/static/mutation_test.py` (a step of `checkers`).
* **No `[a | prop]` as the result of a `prfn`**: such a return silently dropped the
  proposition (the guards `[p; q] void` were checked by mutants and are not dropped), so
  return a dataprop (an `EQI`, a `LEN`), or state it with a `prfun`.

## The only way to change a record

`libstore_save_book` and `libstore_save_index` (`idb_update`, bridge: one transaction in
which a key is read, the closure decides from what it read and the answer is written
back, kept as it was or deleted). The closure reads the stored record, decodes it, puts
the groups of the image that changed into it (`book_record_patch`: the other groups and
the chunks it does not know stay as they were), writes it, and answers `BookSaved`,
`BookRefused` (undecodable: `Newer`, `NotQuire`; nothing is written) or `BookNotSaved`. A
record that lost a group is repaired and its old bytes kept in the same transaction.
**Nothing else writes `library/` keys** (`tests/static/keys.py` fails the checkers on a
`"library/` key named outside `src/libstore.bats`).

**What the library keeps in memory** (`src/library.bats`): the books and collections, and a
shadow of each record (`shadows`, `index_shadow`): the image of what was last sent.
`lib_save` compares each book's image with its shadow by group (`book_image_diff`) and
sends the groups that differ. A shadow is set when its groups are sent, not when kept,
so a change sent and changed back before the first is kept is still sent; a save that is
refused or fails puts the shadow back (`_shadow_unsend`) and says so once. A book whose
record is no longer in the library has its record deleted; a stale tab sends only its own
groups, so two tabs changing different parts of a book keep both changes.

**The order and the view.** A book's record holds its place in the library's order
(`ORDR`, the `position` when last saved) and the books are read back in it. The view kept
for a reload names its book by id (`lib_index_of_id`); a view kept before, of a key alone,
is found by the key.

**The old record** `"lib"` (QLB1 to QLB6) is converted once (`_convert_legacy`): when no
record of the library is there, "lib" is read, shown and written as the records of its
books and the collections' (with its size and byte sum, `LEGA`) in one transaction
(`batch_commit`, bridge's `idb_write_all`), all or none; until it commits nothing is saved.
"lib" itself is never changed or deleted, so an older Quire still finds it; a "lib" that is
not a QLB1 to 6 record is a library that could not be read.

## How far through the book: by the text's size, to the text's end (#426)

`_progress` (the library card and Book info) once counted every spine item the same;
the footer and scrubber weigh chapters by size (`book_weights`). One rule now:

* **By size, not by spine item.** Readium's positions are a resource's size in 1024-byte
  steps, Kobo's percentage follows words or size, Kindle's location is size too. Only a
  fixed-layout book counts items: `book_weights` gives each chapter 1 when every chapter is
  a fixed page (`book_all_fixed`). The size is the entry's size in the archive (compressed
  size; the uncompressed size is not carried to the chapters yet).
* **The text's end is 100%.** The EPUB 3 landmarks' `backmatter` entry (`PartEnd` in
  `src/toc.bats`) names the first chapter of the back matter; `toc_build` hands it to
  `book_text_end_set`, and from that chapter on `book_weights` gives nothing, so the back
  matter reads 100% and the scrubber, ticks and time left follow. A book with no such
  landmark counts all of it; `epub:type` inside a chapter is not read; a `backmatter`
  landmark at the first chapter is no end.
* **The page's start, but the last page of the text is 100%** (`_permille`): the footer
  says where the page starts (a first page is 0%, a second "<1%"). The book is finished
  (`done`) when the percentage is 100% (`_weighed_stored` >= 1001 in `_record_position`).
* **Stored once, carried with the place.** The library cannot weigh a book it has not
  opened, so the reader keeps the thousandth of the place (`progress_weighted`: the
  thousandth plus one, 0 when never worked out, decoded once into a `progress_basis`,
  `ByChapters | Weighed`) beside the place whenever it saves it. It is the record's `prog`
  group (lower case, ancillary), the backup's and sync file's `progressWeighted` (slot
  `SLOT_PROGRESS_WEIGHTED`, taken whenever the place is, `_take_place`) and the 18th number
  of an orphan record ("QO1"). A file without it gives 0: counted by chapters until read
  here.

`e2e/progress.spec.js` (books in `e2e/progress-books.js`) plays each case, and backup and
sync carrying the number (`e2e/sync.spec.js`).

## Replace keeps what the reader made (#425)

A book's id is the SHA-256 of its file (`_file_id` in `src/import.bats`), so the duplicate
question (Skip / Replace) is asked only for a file already in the library byte for byte;
an archived book is put back by importing it with no question. **Replace** (`import_mode`
`Replace`) changes the book's file (one `b<id>` entry), size, series and cover (when the
file has one) and nothing else: place, collections, finished mark, minutes, annotations,
notes, order, id and a hidden book's shelf stay; only an archived book or one in the Trash
comes back to the Library. `e2e/replace.spec.js` holds the whole record, the file's size
and the card before and after to be the same, and plays a backup, a second device and a
second tab over it. (Apple Books and Kobo make a corrected file a new book and the notes
stay with the old one; users complain.)

* **A corrected file** has another id. When the OPF of a new file is read (`_opf_done`),
  its title and author are compared with the library's (`lib_find_similar`: case and
  surrounding white space ignored, an empty title never matches, a book in the Trash is
  not one); a match asks "Newer file of a book?" (`QNewerFile`, `_ask_newer`): **Replace**
  or **Add as new book** (also Escape: nothing is lost either way). Nothing has been
  stored by then (`BookLooksLike`); after the answer the OPF is read again as `Replace`
  (stored under the *book's* id) or `AddAlone`.
* **Chapters are found by name.** The hrefs of a book's chapters (`src/chapter_hrefs.bats`)
  are kept under the key `h<id>`, written when a book is opened and by every replace. A
  replace makes a `chapter_map` with the new file's hrefs (`MapByHref`; `MapByNumber` when
  the old file's were not kept: the same number when the count is the same) and moves:
  * the place (`_place_moved`): the chapter of its href, at the same page and anchor; else
    the chapter of the same number if there are as many, else the first at its start;
    progress weights are counted anew.
  * each note (`annot_reanchor`, `_relocate`): its chapter's new number; one whose chapter
    is not in the new file is kept under `LOST_CHAPTER` + its old chapter, listed after
    every chapter under "Not found in this version", painted nowhere, exported with that
    heading. A note's id contains its chapter, so a moved note has its old id deleted (a
    tombstone) and sync passes on a deletion and a new note. A note of a chapter that
    exists but lacks the node it names is lost the same way when the chapter is shown
    (`annot_chapter_shown`); a changed word is not noticed.
* **Another tab** (`src/file_version.bats`): bridge has no channel between tabs, so a tab
  that has a book open asks, when shown again (`visibilitychange`, the moment sync runs),
  which file the book is made from: the key `v<id>` holds the file's id when it is not the
  book's own (deleted when the book's own file comes back). If it is not the file the tab
  opened, the tab goes to the library and the banner says "This book was replaced with
  another file in another tab" with Reopen Quire (`BookReplacedElsewhere`). An identical
  file changes nothing. `e2e/replace-corrected.spec.js` (`e2e/replace-books.js`).

## A library that cannot be read says why, and offers what fits (#374)

Bridge's IndexedDB read says why it failed: `Unreadable(cause)` carries a `browser_reason`
(the DOMException's name decoded once there). `src/unreadable.bats` turns it into a flat
`failure_kind` (`KindTransient`, `KindStorageBlocked`, `KindNewerVersion`, `KindAborted`,
`KindNoReasonGiven`, `KindBytesUnreadable`, `KindUnexpected`); `library_content`
(`src/libstore.bats`) matches the lookup itself, where `lookup_content` folds every cause
into `ContentUnreadable`, and `library_read.ReadFailed` carries a `failure_found` (the kind
and, for an unexpected one, the name and message cut at 4096 bytes). **A read of storage that
failed is never taken for an empty one** (#174): `lookup_bytes` and `lookup_content`
(`src/book.bats`) answer `StoredUnreadable` / `ContentUnreadable` apart from nothing stored,
so every load must say what it does then. A record each save rewrites whole (settings,
statistics, reading speed, catalogues, dictionaries, sync's state, a book's annotations)
that could not be read is not saved this session (`src/storage.bats`: `storage_savable`),
and an unread book's annotations cannot be made; the banner says so. A library that could
not be read at all is not saved this session and books are not added to it. A backup that
could not read a book's notes is not made.

* **Hope is a proof.** `HOPE(failure)` is a dataprop with a constructor for `FTransient`
  alone. The screen's `remedy` is `TryAgain(HOPE(f) | failure_is(f))` or `NoRemedy`, made
  only by `remedy_of`, a total `case+`, and `ui_try_again_show` needs the `HOPE(f)`: Try again
  for any other kind does not type-check (`tests/static/reject/try-again-without-hope`).
  **Aborted has no hope**: the IndexedDB specification defines only UnknownError as transient;
  AbortError is raised when a transaction is aborted and Quire's read never aborts, so
  something else did and nothing says it will not again.
* **What the screen says** (`library-empty`, `_unreadable_text` in `src/library.bats`): what
  happened, what Quire did, what to do and the browser's name for it; every text ends "Quire has
  not changed anything and will not save until it can read your library." and none says "Import
  an EPUB". Only Transient has a button. Import is off while the library is unreadable (`inert`
  on `import-file`; a file handed or dropped is refused).
* **Records that cannot be used are set aside, not replaced.** A record that is not Quire's
  or has no header to read (empty, over `RECORD_MAX`, another kind) is shown nowhere and not
  written over by a read; the collections' record, and a book's of a newer Quire or not
  Quire's, are never written over, so no collection can be made while the collections' is
  one of them. Settings shows a row then (`settings-aside`, `lib_aside_show`: "Set aside
  unreadable records"), and only then. Pressing it (`lib_aside_run`, `lib_set_aside`) reads
  the library again and, for each such record, runs `libstore_set_aside_book` /
  `libstore_set_aside_index`: one `idb_update` transaction that decides again with the codec
  and, only for `UnusableDamaged` and `UnusableNotQuire`, writes the bytes to
  `library/damaged/<id>/<crc>` and deletes the record in one batch (`_aside_writeback`), so
  an aborted transaction leaves the old record byte for byte. A newer Quire's record
  (`UnusableNewer`) is never set aside (`AsideNewer`). Nothing is lost, so it is not a `harm`.
  Firefox does the same with a corrupt `places.sqlite`; Quire acts on one record at a time.
* **The banner.** A kind the screen says completely has no banner; only an unexpected failure
  raises one (`notice_unexpected`). Over the library the banner is part of the page, above
  the header, and pushes it down (Material 3), so it is over nothing; over the reader it is
  fixed at the top while the bars are away and under the top bar while up (`.banner.under-bars`).
  `coveredByBanner` and `toastClear` (`e2e/controls-shown.js`) fail a control under a banner or
  toast. A modal layer is over the status (#556): while a library menu is open the Undo toast
  is under its veil and while a veiled reader panel is open the banner is, both still up
  (`_open_set`, `_modality_show` in `src/layer.bats`: `data-menu`, `data-veil`; never a
  `:has()` on the root, `tests/static/has_root.py`). The details of an unexpected failure
  outlive its banner (`_details`, in memory only) and About shows "Copy last error details"
  (`about-error-copy`). Start-up with a library that could not be read does not write over the
  stored view (`_library_shown(false)`).
* **One honest retry.** Try again repeats the read start-up makes (`lib_load`) through
  `_library_read`, so the `LIBRARY_READ` proof is only made there. `lib_retry_begin` spends the
  retry when it starts, so a second press does nothing. When the first read fails for a reason
  with hope, the start-up steps that wait for the read (`_after_read`: files handed to the app,
  sync, the stored search and view) are held and run once when the retry ends, whichever way; for
  a reason without hope they run at once (the files are kept, not added). `storage_savable` is
  cleared only by `storage_read_again`, given `AttemptRead` by a read that worked.
  `library_view` is `ViewBooks | ViewEmpty | ViewUnreadable(failure_kind)`.
* `e2e/storage.spec.js` stubs the library's read to throw a DOMException of each name
  (`failLibrary`), once or always.
